# Source Manifest

## Project
**YottaFlex Marketing Attribution & Anomaly Detection**

## Data Source

All project datasets are **synthetically generated** for testing marketing attribution, campaign ROI reporting, and anomaly detection. No real customer or confidential marketing data is used.

## Reproducibility

- **Random seed:** `20261022`
- **Primary generator:** `src/generate_data.py`
- **Database schema:** `src/schema.sql`
- **Database setup:** `src/setup_db.py`
- **CSV loader:** `src/load_data.py`

Run the following commands from the project root to regenerate and load the baseline data:

```powershell
python .\src\generate_data.py
python .\src\setup_db.py
python .\src\load_data.py
```

## Attribution Methods

The project generates attribution results using:

- First-touch attribution
- Last-touch attribution
- Linear attribution

Revenue allocation is validated against eligible touchpoints occurring on or before the opportunity conversion time.

## Anomaly Dataset

`src/inject_anomalies.py` creates separate anomalous data files and ground-truth labels for five deliberately injected anomaly types:

1. Duplicate revenue
2. Post-conversion touchpoint
3. Currency mismatch
4. Missing campaign costs
5. Unsupported identity link

The anomalous dataset is separate from the baseline data.

## Validation and Evaluation

Use the following commands to validate the generated datasets and evaluate the injected anomalies:

```powershell
python .\src\validate_data.py
python .\src\validate_attribution.py
python .\src\detect_anomalies.py
python .\src\evaluate_anomalies.py
```

The reported anomaly detection scores measure performance on the deliberately injected test cases only. They do not establish performance on real-world marketing data.

## External Sources

No external datasets are used. All records are generated locally by the project's Python code.
